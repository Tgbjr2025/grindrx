## 9. Lifecycle and Background Behavior

### Android
- **Foreground Service**: `NotificationService` (dataSync type) keeps process alive
- **WebSocket**: Runs in Rust tokio runtime within same process as MainActivity
- **Background survival**: START_STICKY — recreated if killed under memory pressure
- **App Lock**: `set_app_locked` command from frontend → `AppState::locked` gate for notifications
- **Discreet Mode**: Launcher alias toggle via `PackageManager.setComponentEnabledSetting`
- **FLAG_SECURE**: Set on Window — blocks screenshots, recents thumbnail, screen recording

### iOS
- No background service code visible
- Background modes not declared in `Info.plist` or `tauri.conf.json`
- Would need `UIBackgroundModes` for WebSocket keep-alive

### Desktop
- Standard Tauri window lifecycle
- DevTools plugin in debug builds only

## 15. Conclusions and Blockers

### Android: READY WITH DRIFT
- **Source and toolchain complete** — all dependencies, permissions, native code, signing config present
- **Critical blocker:** Version drift must be resolved before any release (`tauri.android.init` regeneration required on build host)
- **CI gap:** No Android cross-compilation or APK build in CI
- **Device validation:** None — all features unverified on hardware

### iOS: SOURCE ONLY
- **Source config complete** — Info.plist, capabilities, icons, build scripts
- **No generated project** — `gen/apple` created on-demand
- **No CI, no build verification, no device validation**
- **Background modes not configured** — WebSocket keep-alive won't work

### Desktop: CONFIGURED BUT UNBUILT
- **Capabilities and config present** for Linux/macOS/Windows
- **No release profile in Cargo.toml** — default profile (no LTO, no strip, 16 codegen units)
- **No CI, no build verification, no device validation**

### Version Consistency: CRITICAL FAILURE
Three different version tuples in the repository. Any release built without regenerating `tauri.properties` will ship wrong versionCode.

### Signing: ANDROID READY, IOS DEVELOPMENT ONLY
- Android: Production JKS configured, certificate verified across multiple sources
- iOS: Development team configured, no distribution certificate/provisioning profile for App Store
- Desktop: macOS dev identity only
